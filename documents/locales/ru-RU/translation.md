# Правила перевода на русский язык

## Ресурсы и структура

[Английский словарь ресурсов](../en-US/strings.yml) — единственный источник текста. Правила проекта описаны в [руководстве по сопровождению документации](../../maintenance.md). Начиная новый перевод, скопируйте английский файл целиком в `strings.yml` в этом каталоге. Сохраните первую строку `### YamlMime:Resources` и кодировку UTF-8. При обновлении учитывайте изменения оригинала, не перезаписывая существующие переводы. Этот файл `translation.md` сохраняется постоянно и не публикуется на сайте.

Навигация, порядок глав, якоря, ссылки, форматирование, код и изображения общие для всех языков и находятся вне `locales/`. Не добавляйте в этот каталог статьи, TOC, шаблоны, сценарии или настройки.

При переводе меняйте только значения в `strings.yml` этого языка. Набор ключей должен точно совпадать с английским. Не добавляйте, не удаляйте и не переименовывайте ключи по собственной инициативе, даже если тексты похожи или ещё не встретились в интерфейсе. Об ошибке в оригинале сообщите сопровождающим проект, указав ключ и суть проблемы. Сначала исправляются английский текст и общие страницы, затем переводы.

## Стиль и контекст

Используйте стиль технического учебного пособия: точный, сдержанный и понятный. Сначала объясняйте связь операций, затем условия и ограничения. В уроках сохраняйте конкретные действия и проверяемые результаты. Научная точность не требует тяжёлых пассивных конструкций или длинных фраз.

Редактируйте статью в порядке чтения, учитывая соседние абзацы, таблицы и код. Ключ — граница хранения, а не самостоятельная единица перевода. Проверяйте падежи, предлоги и согласование ссылок и выделенных фрагментов в полном предложении.

В заголовках, подписях элементов интерфейса, коротких видимых текстах главной страницы и подписи подвала не ставьте конечную точку. В абзацах, диагностике и инструкциях доступности сохраняйте обычную пунктуацию. Для каждого понятия используйте один принятый термин; не добавляйте выборочно английские пояснения в скобках. Идентификаторы API, файлов и настроек сохраняйте.

Сохраняйте предложение, если оно объясняет текущую операцию, проектное решение, проверяемый результат или необходимое условие. Удаляйте перечни неиспользуемых возможностей, общие оговорки и повторные требования. Заголовки и фразы, разделённые оформлением, переводите целиком, с естественным русским порядком слов. Позиции `{accent}` и `{lineBreak}` в заголовке главной страницы можно менять: оформление не должно закреплять английский синтаксис. Удаление абзаца и его ключей сопровождающий согласованно выполняет в оригинале, общей разметке и словарях всех языков.

## Текст и заполнители

Переводите предложения или абзацы целиком ясным и естественным техническим русским языком. Сохраняйте условия, отрицания, единицы измерения, порядок действий и ограничения времени жизни. Не добавляйте технических гарантий, требований к платформе, версий пакетов или примечаний к выпускам, которых нет в оригинале. Названия продуктов, пакетов и файлов, а также идентификаторы C# и Slang сохраняйте без изменений, включая регистр.

Каждое значение должно быть непустой строкой обычного текста, без HTML и Markdown. Соблюдайте правила кавычек и экранирования YAML. При необходимости заключайте значения в кавычки, чтобы двоеточия, решётки или текст, похожий на число, не были истолкованы неверно. Для удобства сверки сохраняйте английский порядок ключей.

Именованные заполнители, например `{context}` и `{link}`, могут подставлять код, ссылки или выделенный текст из общих страниц. Заполнители интерфейса, такие как `{name}`, `{query}` и `{count}`, могут также получать обычный текст во время выполнения. Проверяйте использование ресурса на соответствующей странице или в интерфейсе, не определяя содержимое только по имени. Подписи ссылок и выделенный текст с отдельными ключами ресурсов тоже нужно переводить.

Порядок заполнителей можно менять согласно русскому синтаксису. В каждом ключе сохраняйте все имена, их регистр и фигурные скобки ASCII. Не добавляйте, не удаляйте и не переименовывайте заполнители; не заменяйте их отображаемыми именами API, подписями ссылок или числами из примеров. Не разделяйте ключи ресурсов ради перестройки предложения.

## Ссылки на API и технический смысл

Ссылки поддерживаются в общих страницах. Идентификаторы, явно обозначающие локальный API в тексте и таблицах, ведут к соответствующему типу или члену. Переменные, имена параметров, типы из примеров, названия пакетов и файлов, а также внешние символы без локальной справочной страницы остаются обычным текстом кода. Одинаковое написание не всегда означает один и тот же символ. В обычные блоки кода учебника ссылки автоматически не добавляются. Можно перемещать заполнитель целиком, но нельзя менять ссылки, общий код или его форматирование.

Если для API не создан справочный элемент, его идентификатор остаётся обычным текстом кода на общей странице, а рядом размещается явно обозначенная ссылка на исходный код. Не заменяйте её ссылкой на другой тип или член.

Сохраняйте следующие различия:

- Запись команд, их отправка, выполнение на GPU и завершение — разные этапы.
- Назначение ресурса, резидентность памяти или предполагаемый доступ CPU, состояние доступа к текстуре (layout) и формат пикселя — разные понятия.
- Владение означает ответственность за освобождение ресурса. Один лишь дескриптор не продлевает время жизни ресурса; отправка команд не передаёт владение.
- Завершение работы GPU не всегда означает, что промежуточные данные считывания уже скопированы в целевую память CPU приложения. Сохраняйте указания об ожидании очереди, управляющей этой операцией.
- Drawable — выходная текстура текущего кадра, не обязательно изображение цепочки обмена. Различайте представления ресурсов и элементы управления интерфейса.

## Сборка и проверка перед передачей

Выполняйте команды из корня репозитория в среде с требуемым проекту .NET SDK и установленным DocFX. В новой копии репозитория ещё нет сгенерированных метаданных в `documents/api/`. Сначала выполните полную сборку, включающую извлечение API:

```sh
docfx documents/docfx.json --warningsAsErrors
```

Если метаданные API уже созданы и соответствуют текущему исходному коду, для изменений только в словаре достаточно обычной сборки и предпросмотра:

```sh
docfx build documents/docfx.json --warningsAsErrors
docfx serve documents/_site --hostname 127.0.0.1 --port 8080
```

Этот язык уже зарегистрирован. Полный словарь становится доступен после успешной сборки без изменения настроек. Отсутствующие или лишние ключи, пустые значения, значения другого типа и несовпадающие имена заполнителей приводят к ошибке сборки. Сборка не выявляет неточный перевод или оставшийся английский текст: необходима ручная вычитка.

Все языки используют одинаковые пути страниц. `?lang=ru-RU` выбирает русский язык; при переключении сохраняются путь и якорь. Без явного указания сначала учитывается сохранённый ручной выбор, затем языковые настройки браузера, затем английский. Если этот перевод ещё не опубликован либо загрузка или проверка ресурсов страницы завершается ошибкой, страница отображается на английском без смешивания языков по предложениям. Список языков отсортирован по коду.

Перед передачей сверьте ключи и заполнители. Проверьте главную страницу, входную страницу Learn, учебник с треугольником, концепции, примеры и интерфейс справочника API на настольном экране и при ширине 320 пикселей. Пройдите учебник с позиции начинающего: проверьте термины, кнопки, поиск, копирование кода, ссылки на API и положение раздела после смены языка. Идентификаторы, объявления и код остаются общими; переводится только текст словаря. Тестовые словари и временные файлы проверки храните вне репозитория; не сдавайте перевод с текстом-заглушкой.

## Терминология

DirectX 12, Metal 4 и Vulkan 1.4 называйте «графическими API», а поддерживающие их код и пакеты — «реализациями соответствующих API».

| Английский термин | Принятый вариант                                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------------------------- |
| API / GPU / RHI   | Сохранять сокращения и пояснять их по оригиналу                                                               |
| barrier           | барьер                                                                                                        |
| buffer            | буфер; `Buffer` не изменять                                                                                   |
| command buffer    | командный буфер                                                                                               |
| command queue     | очередь команд                                                                                                |
| drawable          | выходная текстура текущего кадра; `Drawable` не изменять и не считать обязательно изображением цепочки обмена |
| graphics API      | графический API                                                                                               |
| graphics context  | графический контекст                                                                                          |
| pipeline          | конвейер                                                                                                      |
| readback          | считывание данных с GPU                                                                                       |
| render pass       | проход рендеринга                                                                                             |
| resource          | ресурс                                                                                                        |
| shader            | шейдер                                                                                                        |
| swap chain        | цепочка обмена                                                                                                |
| texture           | текстура                                                                                                      |
| timeline          | временная шкала                                                                                               |
| upload            | загрузка данных на GPU                                                                                        |
