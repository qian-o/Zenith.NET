# 日本語翻訳ガイド

## リソースと構成

[英語のリソース辞書](../en-US/strings.yml)を唯一の原文とします。プロジェクトの規約は[ドキュメント保守ガイド](../../authoring.md)を参照してください。新しい翻訳を始めるときは、英語のファイル全体をこのディレクトリの `strings.yml` にコピーします。先頭行の `### YamlMime:Resources` と UTF-8 エンコーディングを維持してください。更新時は英語の変更点を既存の訳文に反映し、ファイル全体を上書きしないでください。この `translation.md` は翻訳後も保持し、サイトには公開しません。

ナビゲーション、章の順序、アンカー、リンク、書式、コード、画像は `locales/` の外で共通管理します。このディレクトリに記事、TOC、テンプレート、スクリプト、設定を追加しないでください。

翻訳では、この言語の `strings.yml` の値だけを変更します。キーの集合は英語と完全に一致させます。同じ文言に見えるキーや、まだ画面で見ていないキーも含め、独自の追加・削除・改名はしません。原文に問題があれば、該当キーと問題点を保守担当者に伝えてください。英語と共通ページを先に修正し、その後で訳文を更新します。

## テキストとプレースホルダー

文または段落全体を、簡潔で自然な「です・ます」調の日本語に翻訳します。前提条件、否定、単位、操作順序、リソースの有効期間に関する制約を維持してください。原文にない技術的な保証、プラットフォーム要件、パッケージのバージョン、リリース情報を追加しません。製品名、パッケージ名、ファイル名、C# と Slang の識別子は、大文字と小文字も含めて変更しません。

値はすべて、空でない文字列のプレーンテキストにします。HTML や Markdown は記述しません。YAML の引用符とエスケープに注意し、コロン、シャープ記号、数値に見える値などが誤って解析されないよう、必要に応じて引用符で囲みます。照合しやすいよう、キーの順序も英語に合わせてください。

`{context}` や `{link}` などの名前付きプレースホルダーには、共通ページのコード、リンク、強調表示が入る場合があります。UI の `{name}`、`{query}`、`{count}` などには、実行時に通常のテキストが入る場合もあります。名前だけで内容を判断せず、対応するページや UI での使われ方を確認してください。リンクのラベルや強調される文言に独立したリソースキーがあれば、その値も翻訳します。

日本語の語順に合わせてプレースホルダーを移動できます。ただし、各キーのすべての名前、大文字と小文字、半角の波括弧を維持してください。追加・削除・改名や、表示された API 名、リンクのラベル、例示の数値への置き換えはしません。文を組み直すためにリソースキーを分割しないでください。

## API リンクと技術的な意味

リンクは共通ページで管理します。本文と表でサイト内の API を明示する識別子は、対応する型またはメンバーにリンクします。変数、パラメーター名、サンプル独自の型、パッケージ名、ファイル名、サイト内に参照ページのない外部シンボルは通常のコード表記のままです。同じつづりでも同じシンボルとは限りません。通常のチュートリアルのコードブロックには、自動でリンクを追加しません。プレースホルダー全体は移動できますが、リンク先、共通コード、その書式は変更しないでください。

API の参照項目が生成されていない場合、共通ページでは識別子を通常のコード表記にし、その近くにソースコードへのリンクを明示します。別の型やメンバーへのリンクに置き換えないでください。

特に次の区別を維持してください。

- コマンドの記録、サブミット、GPU での実行、完了は別の段階です。
- リソースの用途、メモリの常駐特性や想定する CPU アクセス、テクスチャレイアウト、ピクセル形式は異なる概念です。
- 所有権はリソースを解放する責任を表します。ハンドルだけではリソースの存続は保証されず、コマンドのサブミットで所有権が移るわけでもありません。
- GPU の処理が完了しても、一時領域のリードバックデータがアプリケーションの CPU 側の転送先にコピー済みとは限りません。処理を管理するキューでの待機に関する説明を維持してください。
- drawable は現在のフレームの出力テクスチャであり、必ずしもスワップチェーンの画像ではありません。リソースビューと UI コントロールも文脈に応じて区別してください。

## ビルドと提出前の確認

プロジェクトに必要な .NET SDK と DocFX がある環境で、リポジトリのルートから実行します。新しくチェックアウトしたリポジトリには、`documents/api/` の生成メタデータがまだありません。最初に API の抽出を含む完全なビルドを実行してください。

```sh
docfx documents/docfx.json --warningsAsErrors
```

API メタデータが生成済みで現在のソースコードと一致している場合、辞書だけの変更には通常のビルドとプレビューを使えます。

```sh
docfx build documents/docfx.json --warningsAsErrors
docfx serve documents/_site --hostname 127.0.0.1 --port 8080
```

この言語は登録済みです。完全な辞書でビルドが成功すると、設定を変更せずに利用できます。キーの不足・余剰、空の値、文字列以外の値、プレースホルダー名の不一致はビルドエラーになります。翻訳の正確さや英語の訳し残しはビルドでは判定できないため、人による通読が必要です。

全言語でページのパスを共有し、`?lang=ja-JP` で日本語を選びます。言語を切り替えてもパスとアンカーは維持されます。明示的な指定がない場合は、保存済みの手動選択、ブラウザーの言語設定、英語の順に選ばれます。この訳文が未公開の場合や、辞書の読み込み・ページのリソース検証に失敗した場合は、文ごとに言語を混在させず、英語でページを表示します。言語一覧は言語コード順です。

提出前にキーとプレースホルダーを照合し、ホーム、Learn の入口、三角形チュートリアル、概念、サンプル、API の UI をデスクトップと幅 320 ピクセルで確認してください。初心者の順序でチュートリアルを読み、用語、ボタン、検索、コードのコピー、API リンク、言語切り替え後の節の位置を確認します。識別子、宣言、コードは共通のまま、辞書が提供する本文と UI の文言だけを翻訳します。テスト用辞書や一時的な確認ファイルはリポジトリの外に置き、仮の訳文を提出しないでください。
