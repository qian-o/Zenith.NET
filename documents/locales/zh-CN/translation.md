# 简体中文翻译约定

## 资源与结构

[英文资源字典](../en-US/strings.yml)是唯一原文；项目约定见[文档维护指南](../../maintenance.md)。开始新译本时，将英文文件完整复制为本目录的 `strings.yml`，保留首行 `### YamlMime:Resources`，使用 UTF-8 编码。后续更新应对照英文变更修订现有译文，不要重新覆盖整个文件。本文件 `translation.md` 永久保留，不发布到网站。

导航、章节顺序、锚点、链接、格式、代码和图片都在 `locales/` 外统一维护。不要在语言目录内新增文章、TOC、模板、脚本或配置。

翻译只修改本目录 `strings.yml` 的值。键集合必须与英文完全一致，不得自行新增、删除或重命名键，包括看起来相同或暂未遇到的界面文案。如果原文存在问题，向维护者指出资源键和问题，由英文及共享页面先统一修正，再同步译文。

## 文风与上下文

采用严谨、自然的技术教材文风，先解释操作之间的关系，再说明条件和限制。教程保留明确的操作步骤与可观察的结果。学术风格不等于增加被动句、抽象名词或长句。

按文章的阅读顺序审校，结合前后段落、表格和代码理解内容。资源键只是存储边界，不是孤立的翻译单元。链接标签和强调片段应放回完整句子检查，避免机械复述、反复请求读者操作，以及不说明实际含义的比喻。

标题、界面标签、首页可见的简短介绍和页脚文案不加句末句号；正文、诊断信息和无障碍操作说明保留正常标点。每个概念使用一种通行译法，不零散附加英文括注。API 标识符、文件名和实际设置项的名称保持准确；括号可用于必要解释，不作为例行的双语标注。

判断一句话是否需要保留，要看它是否解释当前操作、设计选择、可观察结果或正确使用的条件。删去未使用功能的罗列、泛泛的环境提醒和重复前提。标题及跨样式的短语也须整体翻译，不沿用英文语序。首页标题的 `{accent}` 与 `{lineBreak}` 可按中文调整位置，样式和换行不能决定语序。正文删改由维护者先统一更新英文、共享绑定及各语言键集合，再同步译文。

## 文本与占位符

使用自然、简洁的技术中文，以完整句子或段落为单位翻译，保留前提、否定、单位、操作顺序和生命周期约束。不要逐词拼接译文，也不要添加原文没有的技术保证、平台要求、包版本或发布说明。产品名、包名、文件名、C#／Slang 标识符和大小写保持原样。

每个资源值都必须是非空字符串、纯文本，不写 HTML 或 Markdown。注意 YAML 引号和转义，避免冒号、井号或类似数字的值被误解析；需要时使用引号。保留英文键的排列顺序，方便人工核对。

`{context}`、`{link}` 等命名占位符可对应共享页面中的代码、链接或强调内容；`{name}`、`{query}`、`{count}` 等界面占位符也可能由程序填入普通文本。不要凭占位符名称推断内容，应检查对应资源在共享页面或界面中的用途。链接标签或强调文字若有独立资源键，也需要翻译。

可以按中文语序移动占位符，但每个键都必须保留原有名称、大小写和半角花括号，不新增、删除或改名。不要用显示出的 API 名称、链接文字或示例数字替换占位符，也不要拆分资源键来重组句子。

## API 链接与技术含义

链接由共享页面维护。正文和表格中明确指向站内 API 的标识符链接到对应类型或成员；变量、参数名、示例自定义类型、包名、文件名及没有本站参考页的外部符号保持普通代码文字。相同拼写不代表同一个符号。普通教程代码块不自动添加链接。译者可以移动整个占位符，但不补写链接、不修改目标，也不改动共享代码及其格式。

如果某个 API 没有生成的参考条目，共享页面会保留普通代码文字，并在附近提供明确的源码链接。不要自行改成其他类型或成员的链接。

翻译时尤其注意以下区别：

- 命令录制、提交、GPU 执行和完成不是同一步。
- 资源用途、内存驻留／CPU 访问意图、纹理布局和像素格式是不同概念。
- 所有权表示释放资源的责任；持有句柄不等于保活资源，提交命令也不转移所有权。
- GPU 完成不一定表示暂存的回读数据已复制到应用程序的 CPU 目标；保留原文关于等待所属队列的说明。
- `drawable` 指当前帧的输出纹理，不一律等同于交换链图像；资源视图与 UI 控件也要按上下文区分。

## 构建与交付检查

在已具备项目所需 .NET SDK 和 DocFX 的环境中，从仓库根目录运行命令。首次检出时，`documents/api/` 的生成元数据尚不存在，需要先执行包含 API 提取的完整构建：

```sh
docfx documents/docfx.json --warningsAsErrors
```

之后，如果 API 元数据已生成且与当前源码一致，只修改字典时可使用普通构建并预览：

```sh
docfx build documents/docfx.json --warningsAsErrors
docfx serve documents/_site --hostname 127.0.0.1 --port 8080
```

本语言已注册，完整字典经构建成功后即可使用，无需改配置。缺键、多余键、空值、非字符串值或占位符名称不匹配会导致构建失败。构建不会判断译文是否准确或是否仍残留未翻译的英文，必须人工通读。

各语言共用页面路径，通过 `?lang=zh-CN` 选择语言，切换时保留路径和锚点。没有明确指定语言时，依次采用已保存的手动选择、浏览器语言偏好、英文。如果该译本尚未发布，或字典加载／页面资源校验失败时，页面回退到英文，而不是逐句混用语言。语言列表按语言代码排序。

交付前核对键和占位符，并在桌面及 320 像素宽度检查首页、Learn 入口、三角形教程、概念页、示例页和 API 界面。按初学者的顺序通读教程，检查术语、按钮、搜索、代码复制、API 跳转，以及切换语言后的当前章节位置。标识符、声明和代码仍使用共享原文；只翻译字典提供的界面与正文。测试字典和临时检查文件放在仓库外，不提交占位译文。
