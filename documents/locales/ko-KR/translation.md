# 한국어 번역 지침

## 리소스와 구조

[영문 리소스 사전](../en-US/strings.yml)을 유일한 원문으로 사용합니다. 프로젝트 규칙은 [문서 유지 관리 지침](../../maintenance.md)을 참고합니다. 새 번역을 시작할 때는 영문 파일 전체를 이 디렉터리의 `strings.yml`로 복사하고, 첫 줄의 `### YamlMime:Resources`와 UTF-8 인코딩을 유지합니다. 이후에는 영문 변경 사항을 기존 번역에 반영하며, 번역 파일 전체를 원문으로 덮어쓰지 않습니다. 이 `translation.md`는 번역 후에도 보존하며 사이트에는 게시하지 않습니다.

탐색 구조, 장 순서, 앵커, 링크, 서식, 코드 및 이미지는 `locales/` 밖에서 공통으로 관리합니다. 이 디렉터리에 문서, TOC, 템플릿, 스크립트 또는 설정을 추가하지 않습니다.

번역 시에는 이 언어의 `strings.yml` 값만 수정합니다. 키 집합은 영문과 정확히 같아야 합니다. 문구가 같아 보이거나 아직 화면에서 보지 못한 키도 임의로 추가, 삭제하거나 이름을 바꾸지 않습니다. 원문에 문제가 있으면 해당 키와 문제를 유지 관리자에게 알립니다. 영문과 공유 페이지를 먼저 수정한 다음 번역에 반영합니다.

## 문체와 문맥

기술 교재에 맞게 정확하고 차분하며 이해하기 쉬운 문장으로 씁니다. 작업 사이의 관계를 먼저 설명하고 조건과 제약을 이어서 제시합니다. 튜토리얼은 구체적인 절차와 확인 가능한 결과를 유지합니다. 학술적 정확성을 위해 수동태나 긴 문장을 늘릴 필요는 없습니다.

기사는 앞뒤 문단, 표, 코드와 함께 읽는 순서대로 검토합니다. 리소스 키는 저장 경계일 뿐 독립된 번역 단위가 아닙니다. 링크와 강조 구절을 완성된 문장에 넣고 조사와 문장 연결을 확인합니다.

제목, UI 레이블, 홈페이지의 짧은 소개와 바닥글 문구에는 마침표를 붙이지 않습니다. 본문, 진단, 접근성 안내는 정상적인 문장 부호를 유지합니다. 개념마다 통용되는 용어 하나를 일관되게 쓰고 일부 용어에만 영어를 괄호로 덧붙이지 않습니다. API, 파일, 실제 설정 항목의 식별자는 유지합니다.

문장을 남길지는 현재 작업, 설계 선택, 확인 가능한 결과, 올바른 사용 조건을 설명하는지로 판단합니다. 사용하지 않는 기능 목록, 막연한 환경 주의사항, 반복된 전제는 덜어 냅니다. 제목과 스타일로 나뉜 구절도 하나로 번역해 한국어 어순을 따릅니다. 홈페이지 제목의 `{accent}`와 `{lineBreak}`는 옮길 수 있으며 강조와 줄바꿈이 영어 어순을 강제해서는 안 됩니다. 문단을 삭제할 때는 유지 관리자가 영어 원문, 공통 바인딩, 모든 언어의 키를 함께 정리합니다.

## 텍스트와 자리 표시자

문장이나 문단 전체를 명확하고 자연스러운 한국어로 번역합니다. 전제 조건, 부정 표현, 단위, 작업 순서 및 수명 제약을 유지합니다. 원문에 없는 기술적 보장, 플랫폼 요구 사항, 패키지 버전 또는 릴리스 설명을 추가하지 않습니다. 제품명, 패키지명, 파일명과 C# 및 Slang 식별자는 대소문자까지 그대로 유지합니다.

모든 값은 비어 있지 않은 일반 텍스트 문자열이어야 하며 HTML이나 Markdown을 넣지 않습니다. YAML 따옴표와 이스케이프 규칙을 지키고, 콜론, 샵 기호 또는 숫자처럼 보이는 값이 잘못 해석되지 않도록 필요할 때 따옴표를 사용합니다. 검토하기 쉽도록 영문의 키 순서도 유지합니다.

`{context}`, `{link}` 같은 이름 있는 자리 표시자는 공유 페이지의 코드, 링크 또는 강조된 내용을 삽입할 수 있습니다. UI의 `{name}`, `{query}`, `{count}` 등에는 실행 중 일반 텍스트가 들어갈 수도 있습니다. 이름만으로 내용을 추측하지 말고 해당 페이지나 UI에서 쓰이는 문맥을 확인합니다. 링크 레이블이나 강조 문구에 별도의 리소스 키가 있으면 그 값도 번역합니다.

한국어 어순에 맞게 자리 표시자를 옮길 수 있습니다. 단, 각 키의 모든 이름과 대소문자, ASCII 중괄호를 유지해야 합니다. 자리 표시자를 추가, 삭제하거나 이름을 바꾸지 않으며, 화면에 보이는 API 이름, 링크 문구 또는 예시 숫자로 대체하지 않습니다. 문장을 재구성하려고 리소스 키를 나누지 않습니다.

## API 링크와 기술적 의미

링크는 공유 페이지에서 관리합니다. 본문과 표에서 사이트 내 API를 명확히 가리키는 식별자는 해당 형식이나 멤버로 연결됩니다. 변수, 매개 변수 이름, 예제에서 정의한 형식, 패키지명, 파일명 및 사이트 내 참조 페이지가 없는 외부 기호는 일반 코드 텍스트로 유지합니다. 철자가 같아도 같은 기호는 아닐 수 있습니다. 일반적인 튜토리얼 코드 블록에는 링크를 자동으로 추가하지 않습니다. 자리 표시자 전체를 옮길 수는 있지만 링크 대상, 공유 코드 및 서식은 바꾸지 않습니다.

API의 참조 항목이 생성되지 않은 경우, 공유 페이지에서 식별자를 일반 코드 텍스트로 두고 주변에 소스 코드 링크를 명확히 제공합니다. 다른 형식이나 멤버의 링크로 대체하지 않습니다.

특히 다음 차이를 유지합니다.

- 명령 기록, 제출, GPU 실행, 완료는 서로 다른 단계입니다.
- 리소스 용도, 메모리 상주 특성 또는 의도한 CPU 접근, 텍스처 레이아웃, 픽셀 형식은 서로 다른 개념입니다.
- 소유권은 리소스를 해제할 책임을 뜻합니다. 핸들만 보유한다고 리소스의 수명이 유지되는 것은 아니며, 명령 제출로 소유권이 이전되지도 않습니다.
- GPU 작업이 완료되어도 임시 리드백 데이터가 애플리케이션의 CPU 대상에 복사되었다고 단정할 수 없습니다. 작업을 관리하는 큐에서 기다려야 한다는 원문의 설명을 유지합니다.
- drawable은 현재 프레임의 출력 텍스처이며 항상 스왑 체인 이미지인 것은 아닙니다. 리소스 뷰와 UI 컨트롤도 문맥에 맞게 구분합니다.

## 빌드와 제출 전 검토

프로젝트에 필요한 .NET SDK와 DocFX가 설치된 환경에서 저장소 루트에서 명령을 실행합니다. 새로 체크아웃한 저장소에는 `documents/api/`의 생성된 메타데이터가 아직 없습니다. 먼저 API 추출을 포함한 전체 빌드를 실행합니다.

```sh
docfx documents/docfx.json --warningsAsErrors
```

API 메타데이터가 이미 생성되어 있고 현재 소스 코드와 일치하면, 사전만 수정할 때 일반 빌드와 미리 보기를 사용할 수 있습니다.

```sh
docfx build documents/docfx.json --warningsAsErrors
docfx serve documents/_site --hostname 127.0.0.1 --port 8080
```

이 언어는 이미 등록되어 있습니다. 완전한 사전으로 빌드가 성공하면 설정 변경 없이 사용할 수 있습니다. 누락되거나 추가된 키, 빈 값, 문자열이 아닌 값, 일치하지 않는 자리 표시자 이름은 빌드 오류를 일으킵니다. 빌드가 부정확한 번역이나 번역되지 않은 영어를 판단하지는 못하므로 사람이 전체 내용을 읽고 검토해야 합니다.

모든 언어는 같은 페이지 경로를 사용하며 `?lang=ko-KR`로 한국어를 선택합니다. 언어를 바꿔도 경로와 앵커가 유지됩니다. 명시적으로 지정하지 않으면 저장된 수동 선택, 브라우저 언어 설정, 영어 순서로 선택합니다. 이 번역이 아직 게시되지 않았거나 사전 로드 또는 페이지 리소스 검증이 실패하면 문장별로 언어를 섞지 않고 페이지 전체를 영어로 표시합니다. 언어 목록은 언어 코드순으로 정렬합니다.

제출 전에 키와 자리 표시자를 대조하고, 데스크톱 및 320픽셀 너비에서 홈, Learn 시작 페이지, 삼각형 튜토리얼, 개념, 예제, API UI를 확인합니다. 초보자의 순서로 튜토리얼을 읽으며 용어, 버튼, 검색, 코드 복사, API 링크, 언어 전환 후의 절 위치를 점검합니다. 식별자, 선언 및 코드는 공통으로 유지하고 사전이 제공하는 본문과 UI 문구만 번역합니다. 테스트 사전과 임시 검증 파일은 저장소 밖에 두고 임시 문구를 채운 번역을 제출하지 않습니다.

## 용어

DirectX 12, Metal, Vulkan은 "그래픽스 API"로, 이를 지원하는 코드와 패키지는 "각 API의 구현"으로 표현합니다.

| 영어             | 사용할 표현                                                                            |
| ---------------- | -------------------------------------------------------------------------------------- |
| API / GPU / RHI  | 약어를 유지하고 원문에 따라 설명                                                       |
| barrier          | 배리어                                                                                 |
| buffer           | 버퍼. `Buffer`는 유지                                                                  |
| command buffer   | 명령 버퍼                                                                              |
| command queue    | 명령 큐                                                                                |
| drawable         | 현재 프레임의 출력 텍스처. `Drawable`은 유지하며 항상 스왑 체인 이미지로 해석하지 않음 |
| graphics API     | 그래픽스 API                                                                            |
| graphics context | 그래픽스 컨텍스트                                                                      |
| pipeline         | 파이프라인                                                                             |
| readback         | 리드백                                                                                 |
| render pass      | 렌더 패스                                                                              |
| resource         | 리소스                                                                                 |
| shader           | 셰이더                                                                                 |
| swap chain       | 스왑 체인                                                                              |
| texture          | 텍스처                                                                                 |
| timeline         | 타임라인                                                                               |
| upload           | 업로드                                                                                 |
